# Правила работы в этом репозитории

## Контекст
Учебный проект курса PAM (Технический университет Молдовы, ФКТИМ, департамент ПОиА).
Тема T2 FitTrack — дневник тренировок. Flutter 3.47, Dart 3.9+, Material 3.
Автор — студент, защищает работу устно и должен уметь объяснить каждую строку кода.

## Обязательные правила
1. Одна лабораторная = одна ветка `lab/LN-краткое-описание` = один Pull Request.
2. Коммиты маленькие и атомарные, Conventional Commits на английском:
   feat:, fix:, refactor:, test:, docs:, chore:.
   Один коммит = одна логическая вещь. НИКОГДА не коммить всю лабу одним коммитом.
3. После каждой значимой правки запускай: flutter analyze && flutter test.
   Не коммить, если analyze даёт ошибки.
4. Никаких заглушек TODO в сдаваемом коде. Код должен компилироваться и запускаться.
5. Комментарии в коде — на русском, объясняющие «почему», а не «что».
6. После каждой задачи дописывай docs/EXPLAIN/LN.md:
   - что добавлено (файлы, классы),
   - зачем и какая была альтернатива,
   - какие вопросы может задать преподаватель и как на них отвечать.
7. Архитектура: lib/features/<feature>/{presentation,domain,data}, lib/core/ для общего.
8. Версии пакетов не выдумывай — проверяй на pub.dev перед добавлением.
9. Перед началом работы выводи план из 3-7 пунктов и жди подтверждения.
10. В конце каждой сессии обновляй docs/PROGRESS.md: статус, что сделано, решения, следующий шаг.
