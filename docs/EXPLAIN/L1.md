# L1, часть B — упражнения на Dart

Все файлы лежат в `dart_exercises/`, запуск: `dart run dart_exercises/eN_*.dart`.
`pubspec.yaml` без зависимостей: нужен только для того, чтобы `dart analyze`
знал версию SDK (`^3.9.0`).

## E1. Переменные и null safety — `e1_null_safety.dart`

**Что добавлено:** функция `int parseOrDefault(String? input, int fallback)` и `main()`
с четырьмя примерами из ТЗ.

**Как работает:**
1. `String?` означает, что строка может быть `null`. `int.tryParse` принимает только
   `String`, поэтому сначала проверяем `if (input == null) return fallback;`.
2. После этой проверки Dart сам сужает тип `input` до `String` (type promotion),
   поэтому оператор `!` не нужен.
3. `int.tryParse(input)` вернёт `int?`: число или `null`, если строка не целое число
   (`'abc'`, `'7.5'`). `?? fallback` подставляет значение по умолчанию вместо `null`.

**Альтернативы:**
- `int.tryParse(input ?? '') ?? fallback` — одна строка: `null` превращается
  в пустую строку, а `tryParse('')` тоже даёт `null`. Короче, но хуже читается.
- `int.parse` + `try/catch` — бросает `FormatException`. Исключения для обычного
  «неверного ввода» — лишнее, поэтому ТЗ и требует `tryParse`.
- `int.parse(input!)` — упадёт на `null`. Запрещено ТЗ.

**Вопросы преподавателя:**
- *Что делает `??`?* Возвращает левое значение, если оно не `null`, иначе правое.
  `a ?? b` — это `a != null ? a : b`.
- *Чем `??` отличается от `?.` и `!`?* `?.` вызывает метод, только если объект не
  `null`, иначе всё выражение даёт `null` (`input?.length`). `!` говорит компилятору
  «здесь точно не `null`»; если это неправда, будет ошибка во время выполнения.
- *Почему `'7.5'` даёт `-1`?* `int.tryParse` разбирает только целые числа; для дробных
  есть `double.tryParse`.
- *Почему после `if` не нужен `!`?* Flow analysis: компилятор видит, что при `null`
  мы уже вышли из функции, и дальше считает `input` типом `String`. Это работает для
  локальных переменных и параметров, но не для полей класса.
- *`final` и `const`?* `final` присваивается один раз, значение может вычисляться
  во время выполнения. `const` — значение известно уже при компиляции.

## E2. Коллекции и функциональные методы — `e2_collections.dart`

**Что добавлено:** функция `double promotedAverage(List<int> grades)` и `main()`
с тремя примерами из ТЗ. Циклов `for`/`while` нет.

**Как работает:**
1. `grades.where((g) => g >= 5)` оставляет только проходные оценки. `(g) => g >= 5` —
   анонимная функция (лямбда): для каждой оценки возвращает `true`/`false`.
2. `.toList()` — `where` возвращает ленивый `Iterable`: фильтр выполняется не сразу,
   а при каждом обходе. Дальше мы обходим результат трижды (`isEmpty`, `reduce`,
   `length`), поэтому один раз сохраняем его в список.
3. `if (passed.isEmpty) return 0.0;` — требование ТЗ и защита от ошибки:
   `reduce` на пустой коллекции бросает `StateError`.
4. `passed.reduce((a, b) => a + b)` — сворачивает список в одно значение:
   `((9 + 7) + 10) + 5 = 31`.
5. `sum / passed.length` — оператор `/` в Dart всегда даёт `double` (`31 / 4 = 7.75`).
   Целочисленное деление — это отдельный оператор `~/`.

**Альтернативы:**
- `fold(0, (sum, g) => sum + g)` — как `reduce`, но с начальным значением, поэтому
  на пустом списке не падает (вернёт 0). Проверка `isEmpty` всё равно нужна, иначе
  было бы деление `0 / 0 = NaN`.
- Цикл `for` с накоплением суммы — запрещён ТЗ.
- `map` здесь не нужен: оценки не преобразуются, только фильтруются и суммируются.

**Вопросы преподавателя:**
- *Чем `reduce` отличается от `fold`?* `reduce` берёт первый элемент как начальное
  значение и падает на пустой коллекции; тип результата совпадает с типом элементов.
  `fold` принимает начальное значение явно и может вернуть другой тип.
- *Почему `9.666666666666666`, а не `9.67`?* `29 / 3` — число `double` (IEEE 754),
  `print` выводит его полностью. Округление для показа — `toStringAsFixed(2)` (см. E3).
- *Что такое ленивый `Iterable`?* `where`/`map` не создают новый список, а описывают
  вычисление, которое выполнится при обходе. `toList()` выполняет его сразу.
- *Зачем `return 0.0`, а не `0`?* Dart принял бы и `0` (литерал подстраивается под
  тип `double`), но `0.0` сразу показывает, что функция возвращает дробное число.

## E3. Именованные и необязательные параметры — `e3_functions.dart`

**Что добавлено:** функция
`String formatPrice(double amount, {String currency = 'MDL', int decimals = 2})`
и `main()` с четырьмя примерами из ТЗ.

**Как работает:**
1. `amount` — позиционный параметр: передаётся первым, без имени.
2. `{String currency = 'MDL', int decimals = 2}` — фигурные скобки делают параметры
   именованными. При вызове пишется имя: `currency: 'EUR'`. Порядок именованных
   параметров не важен, и их можно не передавать — тогда берётся значение после `=`.
3. `amount.toStringAsFixed(decimals)` — строка с ровно `decimals` знаками после точки
   и с округлением: `12.5 → "12.50"`, `99.999 → "100.00"`, `7.5` с `decimals: 1` → `"7.5"`.
4. `'${...} $currency'` — интерполяция строк: `${выражение}` для выражений,
   `$имя` для простой переменной.

**Альтернативы:**
- Необязательные *позиционные* параметры в `[]`:
  `formatPrice(double amount, [String currency = 'MDL', int decimals = 2])`.
  Тогда нельзя передать `decimals`, не передав `currency`, а вызов
  `formatPrice(7.5, 'USD', 1)` хуже читается. ТЗ требует именованные.
- `required` для именованного параметра, если значения по умолчанию быть не может
  (например, `{required String currency}`).
- Склеивание строк через `+` — работает, но интерполяция короче и её рекомендует
  стиль Dart.

**Вопросы преподавателя:**
- *Чем именованный параметр отличается от необязательного позиционного?* Именованный
  передаётся по имени (`currency: 'EUR'`), в любом порядке. Позиционный в `[]`
  передаётся по месту, и пропускать можно только параметры с конца списка.
- *Что будет без значения по умолчанию?* Именованный параметр необязательный,
  поэтому его тип тогда должен быть nullable (`String? currency`), либо параметр
  нужно пометить `required`.
- *Почему `99.999` даёт `100.00`?* `toStringAsFixed` округляет по математическим
  правилам, а не просто отбрасывает лишние цифры.
- *Почему деньги в `double` — плохо в реальном проекте?* `double` не может точно
  хранить многие десятичные дроби (`0.1 + 0.2 != 0.3`). В реальных системах суммы
  хранят в целых копейках (`int`) или в десятичном типе. Здесь `double` задан
  сигнатурой ТЗ.

## E4. Классы — `e4_classes.dart`

**Что добавлено:** класс `Student` с полями `name`, `group`, основным конструктором,
именованным конструктором `Student.guest()`, методами `toString`, `==`, `hashCode`
и `main()` с четырьмя примерами из ТЗ.

**Как работает:**
1. `final String name;` — поле нельзя изменить после создания объекта.
2. `Student(this.name, this.group);` — основной конструктор. `this.name` в параметрах —
   сокращение: значение аргумента сразу записывается в поле.
3. `Student.guest() : this('Guest', '—');` — именованный конструктор. У класса в Dart
   может быть только один безымянный конструктор, поэтому дополнительные способы
   создания получают имена. `: this(...)` перенаправляет вызов в основной конструктор.
4. `toString()` с `@override` — `print` вызывает `toString()` у объекта. Без
   переопределения печаталось бы `Instance of 'Student'`.
5. `operator ==` — по умолчанию `==` сравнивает ссылки: `true` только для одного и того
   же объекта в памяти. Мы сравниваем содержимое: `other is Student` проверяет тип
   (и после проверки Dart считает `other` типом `Student`), дальше сравниваем поля.
6. `hashCode` — `Object.hash(name, group)` считает хэш из тех же полей, что и `==`.

**Проверка через `Set`:** `Set` хранит только уникальные элементы. Сначала он сравнивает
`hashCode`, и только при совпадении вызывает `==`. Мы проверили это: во временной копии
класса без `hashCode` оператор `==` давал `true`, а `Set` содержал 2 элемента, потому что
хэши двух разных объектов не совпали. С `hashCode` в `Set` остаётся 1 элемент.

**Альтернативы:**
- `Student.guest() : name = 'Guest', group = '—';` — список инициализации: поля
  задаются напрямую, без перенаправления. Результат тот же.
- `factory Student.guest() => Student('Guest', '—');` — фабричный конструктор: может
  вернуть уже существующий объект или подтип. Здесь это лишнее.
- `name.hashCode ^ group.hashCode` — старый способ. Минус: у `Student('A', 'B')` и
  `Student('B', 'A')` одинаковый хэш. `Object.hash` учитывает порядок полей.
- Пакет `equatable` или `record` — генерируют `==`/`hashCode` автоматически. ТЗ
  требует написать их вручную.

**Вопросы преподавателя:**
- *Почему `==` и `hashCode` переопределяют вместе?* Правило: если `a == b`, то
  `a.hashCode == b.hashCode`. Если его нарушить, `Set` и `Map` работают неправильно:
  в `Set` появляются дубликаты, `Map` не находит ключ.
- *Почему параметр `==` имеет тип `Object`, а не `Student`?* Так объявлен `==` в
  базовом классе `Object`; при переопределении тип параметра нельзя сузить. Поэтому
  тип проверяется внутри через `is`.
- *Что такое `@override`?* Аннотация: «этот метод заменяет метод родителя». Если
  опечататься в имени, анализатор сообщит об ошибке.
- *Что такое `identical(a, b)`?* Проверка «это один и тот же объект в памяти» —
  то, что делал `==` до нашего переопределения.

## E5. Mixin — `e5_mixin.dart`

**Что добавлено:** mixin `Loggable` с методом `log(String msg)`, классы `CartService`
(метод `addItem`) и `AuthService` (метод `login`), которые его подключают, и `main()`
с вызовом из ТЗ.

**Как работает:**
1. `mixin Loggable { ... }` — набор методов, который можно «подмешать» в класс.
   Объект mixin-а создать нельзя (`Loggable()` — ошибка).
2. `class CartService with Loggable` — после `with` класс получает все методы mixin-а,
   как будто они написаны в нём самом. Поэтому внутри `addItem` можно просто вызвать `log(...)`.
3. `runtimeType` — реальный класс объекта во время выполнения. Код `log` один, но у
   объекта `CartService` он печатает `[CartService]`, а у `AuthService` —
   `[AuthService]`.
4. `=>` — короткая запись функции из одного выражения: `void f() => g();` то же, что
   `void f() { g(); }`.

**Альтернативы:**
- Базовый класс `class Loggable` и `extends Loggable`. Работает, но у класса в Dart
  только один родитель: если сервис уже наследует что-то другое, логирование не
  подключить. Mixin-ов после `with` может быть несколько.
- Интерфейс (`implements`) — даёт только обязательство реализовать `log`, но не сам
  код: пришлось бы копировать реализацию в каждый класс.
- Передавать имя класса строкой: `log('CartService', ...)`. Дублирование и риск
  ошибиться при переименовании; `runtimeType` берёт имя автоматически.
- `mixin Loggable on SomeBase` — ограничивает, к каким классам можно подключить mixin.
  Здесь ограничение не нужно.

**Вопросы преподавателя:**
- *Чем mixin отличается от наследования?* `extends` — один родитель, отношение «является».
  `with` — подключение готового поведения, mixin-ов может быть несколько.
- *Чем mixin отличается от интерфейса?* Интерфейс (`implements`) задаёт только
  сигнатуры, реализацию пишет каждый класс. Mixin приносит готовую реализацию.
- *Что, если у двух mixin-ов одинаковый метод?* Побеждает тот, что указан последним
  в `with A, B`: mixin-ы накладываются слоями слева направо.
- *Можно ли полагаться на `runtimeType` в продакшене?* Для отладочных логов — да. Но
  при обфускации (`flutter build --obfuscate`) и в вебе имена классов сокращаются,
  поэтому для логики программы `runtimeType` не используют.

## E6. Асинхронное программирование — `e6_async.dart`

**Что добавлено:** функция `Future<String> fetchProfile(String username)` и
`Future<void> main() async`, которая печатает сообщения до и после ожидания.

**Как работает:**
1. `Future<String>` — «обещание» строки, которая появится позже. Функция возвращает
   его сразу, а сама строка будет готова через 2 секунды.
2. `async` в объявлении функции разрешает внутри `await` и автоматически заворачивает
   результат `return` в `Future`.
3. `await Future.delayed(const Duration(seconds: 2));` — ждём 2 секунды, не блокируя
   программу: цикл событий (event loop) в это время свободен для другой работы.
4. В `main` сначала печатается «Загружается…», затем `await fetchProfile(...)`
   приостанавливает `main` на 2 секунды, после чего печатаются профиль и «Готово.».
5. `const Duration(...)` — объект создаётся на этапе компиляции и переиспользуется.

**Проверка задержки:** вывод пропущен через скрипт, который печатает время прихода
каждой строки от первой: профиль и «Готово.» пришли через `+2.01s`.

**Альтернативы:**
- Цепочка `then`:
  `fetchProfile('ana.rusu').then((p) { print(p); print('Готово.'); });` — работает,
  но при нескольких последовательных шагах вложенность растёт, код хуже читается.
- Без `await` (`fetchProfile('ana.rusu');` и сразу `print('Готово.')`) — «Готово.»
  напечаталось бы *до* профиля, а сам профиль потерялся бы: результат никто не ждёт.
- `sleep(Duration(seconds: 2))` из `dart:io` — блокирует весь поток. Во Flutter это
  «замороженный» интерфейс, поэтому для ожидания используют только `Future`.

**Вопросы преподавателя:**
- *Что даёт `async`/`await` по сравнению с блокирующими вызовами?* Во время ожидания
  поток не стоит: event loop обрабатывает другие события (во Flutter — отрисовку,
  нажатия). Блокирующий вызов остановил бы всё.
- *А по сравнению с `then`?* То же самое поведение, но код читается сверху вниз, как
  синхронный, а ошибки ловятся обычным `try/catch` вместо `.catchError`.
- *Dart многопоточный?* Код выполняется в одном потоке (изоляте). Асинхронность — это
  не параллельность, а переключение между задачами, пока одна из них ждёт. Для тяжёлых
  вычислений есть отдельные изоляты (`Isolate.run`).
- *Почему `main` возвращает `Future<void>`?* Функция с `async` всегда возвращает
  `Future`. Можно написать `void main() async`, но `Future<void>` честнее описывает тип.
