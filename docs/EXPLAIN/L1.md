## E1. Переменные и null safety — `e1_null_safety.dart`

**Что добавлено:** функция `int parseOrDefault(String? input, int fallback)` и `main()`
с четырьмя примерами из ТЗ.

**Как работает:**
1. `String?` означает, что строка может быть `null`. `int.tryParse` принимает только
   `String`, поэтому сначала проверяем `if (input == null) return fallback;`.
2. После этой проверки Dart сам сужает тип `input` до `String` (type promotion),
   поэтому оператор `!` не нужен.
3. `int.tryParse(input)` вернёт `int?`: число или `null`, если строка не целое число
   (`'abc'`, `'7.5'`). `?? fallback` подставляет значение по умолчанию вместо `null`.

**Альтернативы:**
- `int.tryParse(input ?? '') ?? fallback` — одна строка: `null` превращается
  в пустую строку, а `tryParse('')` тоже даёт `null`. Короче, но хуже читается.
- `int.parse` + `try/catch` — бросает `FormatException`. Исключения для обычного
  «неверного ввода» — лишнее, поэтому ТЗ и требует `tryParse`.
- `int.parse(input!)` — упадёт на `null`. Запрещено ТЗ.

**Вопросы преподавателя:**
- *Что делает `??`?* Возвращает левое значение, если оно не `null`, иначе правое.
  `a ?? b` — это `a != null ? a : b`.
- *Чем `??` отличается от `?.` и `!`?* `?.` вызывает метод, только если объект не
  `null`, иначе всё выражение даёт `null` (`input?.length`). `!` говорит компилятору
  «здесь точно не `null`»; если это неправда, будет ошибка во время выполнения.
- *Почему `'7.5'` даёт `-1`?* `int.tryParse` разбирает только целые числа; для дробных
  есть `double.tryParse`.
- *Почему после `if` не нужен `!`?* Flow analysis: компилятор видит, что при `null`
  мы уже вышли из функции, и дальше считает `input` типом `String`. Это работает для
  локальных переменных и параметров, но не для полей класса.
- *`final` и `const`?* `final` присваивается один раз, значение может вычисляться
  во время выполнения. `const` — значение известно уже при компиляции.
