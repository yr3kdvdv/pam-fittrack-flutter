# L1, часть B — упражнения на Dart

Все файлы лежат в `dart_exercises/`, запуск: `dart run dart_exercises/eN_*.dart`.
`pubspec.yaml` без зависимостей: нужен только для того, чтобы `dart analyze`
знал версию SDK (`^3.9.0`).

## E1. Переменные и null safety — `e1_null_safety.dart`

**Что добавлено:** функция `int parseOrDefault(String? input, int fallback)` и `main()`
с четырьмя примерами из ТЗ.

**Как работает:**
1. `String?` означает, что строка может быть `null`. `int.tryParse` принимает только
   `String`, поэтому сначала проверяем `if (input == null) return fallback;`.
2. После этой проверки Dart сам сужает тип `input` до `String` (type promotion),
   поэтому оператор `!` не нужен.
3. `int.tryParse(input)` вернёт `int?`: число или `null`, если строка не целое число
   (`'abc'`, `'7.5'`). `?? fallback` подставляет значение по умолчанию вместо `null`.

**Альтернативы:**
- `int.tryParse(input ?? '') ?? fallback` — одна строка: `null` превращается
  в пустую строку, а `tryParse('')` тоже даёт `null`. Короче, но хуже читается.
- `int.parse` + `try/catch` — бросает `FormatException`. Исключения для обычного
  «неверного ввода» — лишнее, поэтому ТЗ и требует `tryParse`.
- `int.parse(input!)` — упадёт на `null`. Запрещено ТЗ.

**Вопросы преподавателя:**
- *Что делает `??`?* Возвращает левое значение, если оно не `null`, иначе правое.
  `a ?? b` — это `a != null ? a : b`.
- *Чем `??` отличается от `?.` и `!`?* `?.` вызывает метод, только если объект не
  `null`, иначе всё выражение даёт `null` (`input?.length`). `!` говорит компилятору
  «здесь точно не `null`»; если это неправда, будет ошибка во время выполнения.
- *Почему `'7.5'` даёт `-1`?* `int.tryParse` разбирает только целые числа; для дробных
  есть `double.tryParse`.
- *Почему после `if` не нужен `!`?* Flow analysis: компилятор видит, что при `null`
  мы уже вышли из функции, и дальше считает `input` типом `String`. Это работает для
  локальных переменных и параметров, но не для полей класса.
- *`final` и `const`?* `final` присваивается один раз, значение может вычисляться
  во время выполнения. `const` — значение известно уже при компиляции.

## E2. Коллекции и функциональные методы — `e2_collections.dart`

**Что добавлено:** функция `double promotedAverage(List<int> grades)` и `main()`
с тремя примерами из ТЗ. Циклов `for`/`while` нет.

**Как работает:**
1. `grades.where((g) => g >= 5)` оставляет только проходные оценки. `(g) => g >= 5` —
   анонимная функция (лямбда): для каждой оценки возвращает `true`/`false`.
2. `.toList()` — `where` возвращает ленивый `Iterable`: фильтр выполняется не сразу,
   а при каждом обходе. Дальше мы обходим результат трижды (`isEmpty`, `reduce`,
   `length`), поэтому один раз сохраняем его в список.
3. `if (passed.isEmpty) return 0.0;` — требование ТЗ и защита от ошибки:
   `reduce` на пустой коллекции бросает `StateError`.
4. `passed.reduce((a, b) => a + b)` — сворачивает список в одно значение:
   `((9 + 7) + 10) + 5 = 31`.
5. `sum / passed.length` — оператор `/` в Dart всегда даёт `double` (`31 / 4 = 7.75`).
   Целочисленное деление — это отдельный оператор `~/`.

**Альтернативы:**
- `fold(0, (sum, g) => sum + g)` — как `reduce`, но с начальным значением, поэтому
  на пустом списке не падает (вернёт 0). Проверка `isEmpty` всё равно нужна, иначе
  было бы деление `0 / 0 = NaN`.
- Цикл `for` с накоплением суммы — запрещён ТЗ.
- `map` здесь не нужен: оценки не преобразуются, только фильтруются и суммируются.

**Вопросы преподавателя:**
- *Чем `reduce` отличается от `fold`?* `reduce` берёт первый элемент как начальное
  значение и падает на пустой коллекции; тип результата совпадает с типом элементов.
  `fold` принимает начальное значение явно и может вернуть другой тип.
- *Почему `9.666666666666666`, а не `9.67`?* `29 / 3` — число `double` (IEEE 754),
  `print` выводит его полностью. Округление для показа — `toStringAsFixed(2)` (см. E3).
- *Что такое ленивый `Iterable`?* `where`/`map` не создают новый список, а описывают
  вычисление, которое выполнится при обходе. `toList()` выполняет его сразу.
- *Зачем `return 0.0`, а не `0`?* Dart принял бы и `0` (литерал подстраивается под
  тип `double`), но `0.0` сразу показывает, что функция возвращает дробное число.
