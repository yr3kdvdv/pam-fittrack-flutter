Дисциплина: Программирование мобильных приложений (PAM)

Лабораторные работы образуют сквозной проект курса: на L1 каждый студент выбирает
одну тему из этого каталога, а на L2–L6 инкрементально строит по выбранной теме одно
и то же Flutter-приложение — вплоть до работающего продукта, интегрированного с
собственным backend-ом и собранного в release-версии.
Как тема отображается на лабораторные и backend.

Этап и Что строится из ТЗ темы
L2
экраны списков/деталей темы как статический
UI (точный список — в этапе L2 темы)
L3
навигация между экранами (go_router) + формы
с валидацией
L4
state management + паттерн Repository с mockданными (модель данных темы)
L5
REST-интеграция с собственным backend-ом:
студент расширяет шаблон курса (доступен на
8 языках) сущностями своей темы; JWTаутентификация, универсальный CRUD,
загрузка файлов, пагинация и
стандартизированные ошибки идут из шаблона
L6
персистентность/offline-кэш, тесты, releaseсборка + защита проекта

Список этапов на странице темы имеет приоритет. Экран аутентификации строится
статически на L2, становится функциональным на L3 (валидация) и подключается к
backend-у на L5. Статусы сущностей и записи «другой стороны» (предложения мастеров,
смена статуса заказа, ответы работодателя и т.п.) во время демонстрации имитируются
через собственный backend студента (Swagger UI / seed-данные).

T2. FitTrack — дневник тренировок
Домен: здоровье и фитнес · Сложность: базовая
Описание: FitTrack — личный дневник тренировок: каталог упражнений по группам мышц и
история тренировочных сессий с длительностью и заметками. Решает проблему тетрадки,
потерянной в раздевалке, — прогресс всегда в телефоне. Целевая аудитория: студенты,
которые регулярно тренируются и хотят видеть свою динамику.
Обязательные экраны (6–8):
Вход / регистрация
Каталог упражнений (поиск + фильтр по группе мышц)
Карточка упражнения (описание, техника, изображение)
Дневник тренировок (список сессий в хронологическом порядке)
Форма новой сессии / редактирования (дата, упражнения, длительность, заметки)
Статистика прогресса (сессии в неделю, суммарная длительность)
Профиль пользователя
Обязательная функциональность по этапам:
L2: статические экраны каталога, карточки, дневника и статистики с «зашитыми»
данными (Material 3).
L3: навигация каталог → карточка и дневник → форма сессии (go_router); форма с
валидацией (числовая длительность, минимум одно упражнение).
L4: состояние дневника + Repository с mock-упражнениями и сессиями.
L5: интеграция с backend-ом: GET /exercises, GET /exercises/{id}, GET/POST /
workout-sessions, PUT/DELETE /workout-sessions/{id}; JWT-аутентификация.
L6: offline-кэш каталога и дневника, тесты, release-сборка.
Модель данных backend:
Exercise(id, name, muscleGroup, description, imageUrl)
WorkoutSession(id, userId, date, exerciseIds, durationMin, notes)
Endpoint-ы: GET/POST /exercises, GET/PUT/DELETE /exercises/{id}; GET/POST /
workout-sessions, GET/PUT/DELETE /workout-sessions/{id}. Аутентификация (POST /
auth/register, POST /auth/login) идёт из шаблона.
Бонус (по желанию): таймер отдыха между подходами; график прогресса по упражнению;
экспорт дневника в CSV.

Лабораторная работа № 1 — Среда
разработки, язык Dart и выбор темы

1. Цели работы
По завершении работы студент способен:
установить и настроить среду разработки Flutter (Flutter 3.35+ / Dart 3.9+) на
собственном компьютере и продемонстрировать чистый запуск команды flutter
doctor;
запустить приложение на эмуляторе Android или на физическом телефоне,
подключённом по USB;
писать и запускать программы на Dart с использованием null safety, коллекций и их
функциональных методов, функций с именованными и необязательными
параметрами, классов, mixin-ов и асинхронного программирования (Future, async/
await);
выбрать тему семестрового проекта из каталога тем в соответствии с правилами
закрепления;
составить мини-спецификацию выбранного проекта объёмом в одну страницу
(экраны, сущности, мотивация).

2. Часть A — Установка среды разработки
Отправная точка для любой операционной системы — официальное руководство:
docs.flutter.dev/get-started. Эталонная версия курса — Flutter 3.35 или новее (включает
Dart 3.9+); проверяйте командой flutter --version.

macOS
Скачайте архив Flutter SDK для macOS (выберите подходящий вариант: Apple Silicon
или Intel) и распакуйте его, например, в ~/development/flutter.
Добавьте SDK в PATH в ~/.zshrc: export PATH="$HOME/development/flutter/bin:
$PATH", затем source ~/.zshrc и проверьте flutter --version.
Установите Xcode Command Line Tools (xcode-select --install) — для целей
Android этого достаточно; iOS-симуляторы требуют полный Xcode и в этой работе
остаются необязательными.
Установите редактор (VS Code + расширение Flutter или Android Studio) и Android
Studio для Android SDK; примите лицензии командой flutter doctor --androidlicenses.
Создайте эмулятор в Android Studio → Device Manager или подключите физический
телефон с включённым USB debugging.
Запускайте flutter doctor до чистого результата.

Итоговая проверка
Контрольный запуск:
flutter doctor
Все существенные разделы должны быть отмечены [✓] (раздела iOS/Xcode может не быть
на Windows/Linux, а на macOS он может остаться неотмеченным, если Xcode не
установлен). Отчёт должен содержать полный текст вывода команды (скопированный
из терминала); скриншоты не требуются. Затем покажите, что устройство видно: flutter
devices.
Финальный шаг: demo-приложение. Создайте и запустите демонстрационное
приложение на эмуляторе или телефоне:
flutter create hello_pam
cd hello_pam
flutter run
Сгенерированное по умолчанию приложение-счётчик должно появиться на экране
устройства (проверьте, что кнопка «+» увеличивает счётчик). Этот шаг выявляет проблемы
Gradle или лицензий, которые flutter doctor не видит.

Типичные проблемы
Android sdkmanager not found / непринятые лицензии → установите Android
SDK Command-line Tools в Android Studio (SDK Manager → SDK Tools), затем
выполните flutter doctor --android-licenses.
flutter: command not found → путь к flutter/bin отсутствует в PATH либо
терминал не был перезапущен после изменения.
Эмулятор не запускается / очень медленный → включите аппаратную
виртуализацию в BIOS/UEFI (Intel VT-x / AMD-V); в Windows используйте
Hyper-V или Android Emulator Hypervisor Driver (AEHD) — старый Intel HAXM
снят с поддержки; в Linux проверьте KVM (kvm-ok).
Странные ошибки при сборке или распаковке → путь установки содержит
пробелы или неанглийские буквы (напр. C:\Users\Штефан чел Маре\...);
перенесите SDK и проекты в простой путь только из ASCII-символов.
Телефон не появляется в flutter devices → установите USB-драйвер
производителя (Google USB Driver из SDK Manager или с сайта
производителя) и проверьте командой adb devices.

3. Часть B — Упражнения на языке Dart
Упражнения решаются в DartPad (dartpad.dev) или локально, в файле, запускаемом
командой dart run, — Flutter-проект не нужен. По каждому упражнению отчёт содержит
исходный код и результат запуска на приведённых примерах. Сигнатуры функций/
классов обязательны; решения демонстрируются и объясняются вживую, на защите.

E1. Переменные и null safety
Напишите функцию, которая преобразует строку, возможно равную null, в целое число,
возвращая значение по умолчанию, когда преобразование невозможно. Используйте
int.tryParse и оператор ??; в коде не должно быть оператора !.
int parseOrDefault(String? input, int fallback)
Примеры запуска:
parseOrDefault('42', 0) → 42
parseOrDefault('abc', 0) → 0
parseOrDefault(null, 7) → 7
parseOrDefault('7.5', -1) → -1 // не целое число

E2. Коллекции и функциональные методы
Дан список оценок студента (целые числа 1–10). Вычислите среднее проходных оценок
(тех, что ≥ 5), используя исключительно цепочки where/map/reduce (или fold) и свойства
вроде length/isEmpty — без циклов for/while. Если оценок ≥ 5 нет, функция возвращает 0.
double promotedAverage(List<int> grades)
Примеры запуска:
promotedAverage([9, 4, 7, 10, 3, 5]) → 7.75 // (9+7+10+5)/4
promotedAverage([10, 10, 9]) → 9.666666666666666
promotedAverage([3, 4, 2]) → 0.0

E3. Функции с именованными и необязательными параметрами
Напишите функцию форматирования цены: позиционный параметр amount, именованный
параметр currency со значением по умолчанию 'MDL' и необязательный именованный
параметр decimals со значением по умолчанию 2 (число знаков после запятой, реализуется
через toStringAsFixed).
String formatPrice(double amount, {String currency = 'MDL', int decimals = 2})
Примеры запуска:
formatPrice(12.5) → "12.50 MDL"
formatPrice(12.5, currency: 'MDL') → "12.50 MDL"
formatPrice(99.999, currency: 'EUR') → "100.00 EUR"
formatPrice(7.5, currency: 'USD', decimals: 1) → "7.5 USD"

E4. Классы
Определите класс Student с полями name и group, а также:
основным конструктором и именованным конструктором Student.guest(),
создающим студента name: 'Guest', group: '—';
методом toString() в формате Student(name, group);
оператором == и hashCode — два студента равны, если у них одинаковые name и
group.
class Student {
final String name;
final String group;
// основной конструктор + Student.guest() + toString + == + hashCode
}
Примеры запуска:
print(Student('Ana Rusu', 'TI-231')); → Student(Ana Rusu, TI-231)
print(Student.guest()); → Student(Guest, —)
Student('Ana Rusu', 'TI-231') ==
 Student('Ana Rusu', 'TI-231') → true
{Student('Ana Rusu', 'TI-231'),
 Student('Ana Rusu', 'TI-231')}.length → 1 // hashCode корректен

E5. Mixin
Определите mixin Loggable с методом log(String msg), который выводит сообщение с
префиксом — именем текущего класса: [ИмяКласса] сообщение (используйте runtimeType).
Примените mixin к двум разным классам — например CartService и AuthService — и
вызовите log из одного метода каждого из них.
mixin Loggable {
void log(String msg) { /* ... */ }
}
class CartService with Loggable { /* addItem(...) */ }
class AuthService with Loggable { /* login(...) */ }
Вызов:
CartService().addItem('Paracetamol');
AuthService().login('ana.rusu');
Вывод:
[CartService] товар добавлен: Paracetamol
[AuthService] пользователь вошёл: ana.rusu

E6. Асинхронное программирование
Напишите асинхронную функцию, имитирующую «загрузку» профиля пользователя: после
задержки в 2 секунды (Future.delayed) она возвращает описательную строку. В main
(объявленном async) вызовите функцию с await и выведите сообщения до и после
ожидания — так, чтобы порядок вывода демонстрировал асинхронное поведение.
Future<String> fetchProfile(String username)
Пример запуска (вторая строка появляется через ~2 секунды):
Загружается профиль пользователя ana.rusu...
Профиль: ana.rusu, группа TI-231, решено упражнений: 42
Готово.

4. Часть C — Выбор темы проекта
Сквозной проект дисциплины строится инкрементально на L2–L6 по одной теме
Результат: мини-спецификация на 1 страницу по предпочтительной теме (первой в
списке), которая становится приложением к отчёту и содержит:
Тема — номер и название из каталога (или название собственной темы);
Целевая аудитория — кто пользуется приложением и какую проблему оно решает
(2–3 фразы);
Список экранов — из раздела обязательные экраны спецификации темы (плюс
запланированные бонусные экраны, если есть);
Сущности — модель данных из спецификации темы (напр. Product, Order) с
основными полями;
«Почему эта тема» — один абзац личной мотивации.

Если к моменту защиты первое предпочтение уже занято, мини-спецификация
адаптируется под закреплённую тему (без повторной подачи отчёта — правка вносится в
приложение по согласованию с преподавателем).

5. Требования к отчёту
Отчёт сдаётся в формате PDF с именем файла PAM_L1_ИмяСтудента.pdf (латиницей, напр.
PAM_L1_AnaRusu.pdf) и содержит:
Стандартный титульный лист: университет (Технический университет Молдовы),
факультет (Вычислительная техника, информатика и микроэлектроника),
департамент (Программная инженерия и автоматика), дисциплина, номер и название
работы, имя студента и группа, имя преподавателя, учебный год;
Часть A: полный текст вывода команды flutter doctor (скопированный из
терминала) и команды flutter devices, а также фраза, подтверждающая запуск
demo-приложения (hello_pam), и название использованного устройства;
Часть B: по каждому упражнению E1–E6 — исходный код и результат запуска на
примерах из условия;
Приложение: мини-спецификация темы проекта на 1 страницу (Часть C).
Отчёт отправляется по каналу, объявленному преподавателем (платформа курса или
электронная почта), и представляется на защите.

6. Защита и критерии оценивания
Защита индивидуальная: студент демонстрирует среду на собственном компьютере,
запускает упражнения по требованию, объясняет любую строку кода и отвечает на
контрольные вопросы. Упражнение, код которого студент не может объяснить, не
засчитывается.
